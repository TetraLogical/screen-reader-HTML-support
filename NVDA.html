How HTML elements are supported by screen readers

Typical HTML element support patterns by screen readers:

  • Announce roles of elements as the user moves through the content
  • Announce accessible names and/or descriptions of controls
  • Announce the text content of elements
  • Announce the start and end of elements
  • Change in voice or pitch as content is announced (e.g. to signify punctuation)
  • Announce states and properties of elements.
  • Emission of a beep or other sound when an element with a particular state or property receives virtual focus
  • Instructions on how to operate interactive elements such as form controls
  • Keyboard navigation, shortcuts and “quick access” lists showing all instances of particular elements on a page

Note: The combination of patterns supported varies from element to element. Support for (and announcements of) some elements can vary between screen reader software.

About NVDA

NVDA (NonVisual Desktop Access) is a free and open source screen reader for Windows. It works with Firefox, Chrome, and Edge.

NVDA: quick commands

NVDA key: Insert (or Caps Lock, configurable) by default.

  • Start/stop NVDA: Control + Alt + N (start) / NVDA + Q (stop)
  • Toggle between "Browse" and "Focus" (forms) mode: NVDA + Space
  • Read all content: NVDA + ↓
  • Stop reading: Control
  • Elements list: NVDA + F7
  • Next/previous link: K / Shift + K
  • Next/previous heading: H / Shift + H
  • Next/previous heading by level: 1-6 / Shift + 1-6
  • Next/previous landmark/region: D / Shift + D
  • Next/previous form field: F / Shift + F
  • Tables:
    • Next/previous table: T / Shift + T
    • Navigate table cells: Control + Alt + Arrow keys
    • Start of a table (or list): Shift + ,
  • Next/previous list: L / Shift + L
  • Next/previous list item: I / Shift + I
  • Next/previous graphic: G / Shift + G

 With href: With href:
  • In all cases, NVDA announces the link role
  • In all cases, NVDA announces the link role before the link label when using reading keys like the arrow keys, but after the link label when using the tab key
  • When a link has both visible text and a title attribute (but no other attributes), NVDA announces the contents of both together when using the tab key, but just the link label when using reading keys like the arrow keys
  • NVDA announces the contents of the aria-label attribute when it is applied to the a element, not the visible text
  • NVDA announces the content referenced using the aria-describedby attribute when the link receives focus via the tab key, but not when the link receives focus via the arrow keys
  • When a link has different visible text, title text, aria-label text, and content referenced via the aria-describedby attribute, NVDA only announces the content of the aria-label attribute and the content referenced using the aria-describedby attribute; the visible text is not announced, nor is the content within the title attribute
  • When a link has the same visible text, title text, and aria-label text, NVDA only announces the aria-label text

Link types:

  • Link: This indicates a link that has not been visited.
  • Visited Link: This indicates a link that has been visited. This is determined by your browser history, not by which links have been selected on the current Web page.
  • Same Page Link: This indicates a link that moves you to another location on the same page.
  • Send Mail Link: This indicates a link that opens a new e-mail message using your default e-mail program.
  • FTP Link: This indicates a link that points to an FTP (File Transfer Protocol) server.
